# Getting Started with Safaricom Daraja APIs

Learn how to set up and integrate Daraja APIs into your application and start accepting M-PESA payments today.

---

## Introduction

Welcome to Safaricom APIs. We provide RESTful API endpoints for accessing M-PESA services, including B2C, C2B, B2B, M-PESA Express, and more. Our APIs use HTTP verbs (GET and POST) with JSON-encoded request parameters and responses.

Our APIs comply with HTTP status codes as defined in RFC 2616. You can invoke API endpoints using REST clients like Postman, command-line tools like Curl, or your preferred programming language. We provide code samples in Curl, Ruby, PHP, Python, NodeJS, and Java.

---

## Terminologies

| Term | Definition |
|------|------------|
| **M-PESA** | A mobile money transfer service in Kenya for storing and transferring money via mobile phones. |
| **Short Code** | A unique number allocated to a Pay Bill or Buy Goods organization for receiving customer payments (5-6 digits). |
| **Pay Bill** | A shortcode used to collect money regularly from customers (e.g., utility bills, school fees). |
| **Buy Goods / Till Number** | A shortcode used for retail purchases of goods and services at merchant outlets. |
| **Command ID** | A unique command that specifies the transaction type (e.g., `BusinessPayment`, `SalaryPayment`, `CustomerPayBillOnline`). |
| **Security Credential** | The encrypted API operator password used to authenticate transaction requests. |
| **Passkey** | A secret key used for encrypting the Password parameter in M-PESA Express (STK Push) requests. |
| **ResultURL** | The endpoint where transaction results are sent via callback after processing. |
| **QueueTimeOutURL** | The endpoint notified when a transaction request times out. |
| **Callback URL** | A publicly accessible URL that receives payment notifications from the API gateway. |

## Authentication

All API calls (except Authorization) require a Bearer access token.

### Step 1: Generate Access Token

**Endpoint:**
- Sandbox: `GET https://sandbox.safaricom.co.ke/oauth/v1/generate?grant_type=client_credentials`
- Production: `GET https://api.safaricom.co.ke/oauth/v1/generate?grant_type=client_credentials`

**Headers:**
```
Authorization: Basic Base64(ConsumerKey:ConsumerSecret)
```

**Response:**
```json
{
  "access_token": "c9SQxWWhmdVRlyh0zh8gZDTkubVF",
  "expires_in": 3599
}
```

> **Note:** Tokens expire after **3600 seconds (1 hour)**. Regenerate before expiry.

### Step 2: Use Access Token

Include the token in all subsequent API requests:
```
Authorization: Bearer c9SQxWWhmdVRlyh0zh8gZDTkubVF
Content-Type: application/json
```

## How to Generate Security Credentials

M-PESA Core authenticates transactions by decrypting the security credentials. Security credentials are generated by encrypting the base64-encoded initiator password with M-PESA's public key (an X509 certificate).

### Algorithm

1. Write the unencrypted initiator password into a byte array.
2. Encrypt the byte array using the M-PESA public key certificate:
   - Use the **RSA algorithm**
   - Apply **PKCS #1.5 padding** (not OAEP)
3. Convert the resulting encrypted byte array into a string using **base64 encoding**.

The resulting base64-encoded string is the **Security Credential**.

```text
SecurityCredential = Base64(RSA_Encrypt(PasswordBytes, MPesaPublicKey, PKCS1Padding))
```

> **Important:** Use the correct public key certificate for the target environment (Sandbox vs. Production). An online encryption tool is available on the Daraja portal test credentials section.

## Creating an HTTP Server for Callbacks

M-PESA APIs are **asynchronous**. Responses are sent to the `CallBackURL` or `ResultURL` you specify. If your server is unavailable, the API Gateway logs a 503 error and discards the results.

### Requirements

- Deploy an HTTP/HTTPS server that accepts **POST** requests
- Your server must be **publicly accessible** over the internet
- Use a valid IP address or domain name
- Production URLs must use **HTTPS** (HTTP is allowed in Sandbox)
- Do not use public URL testers (ngrok, mockbin, etc.) in production

### Local Testing

For local development, use HTTP tunneling tools:
- **Ngrok** — Creates a public URL tunnel to your localhost
- **LocalTunnel** — Exposes local servers to the internet

### Response Timing

- Your server should respond to callback requests promptly
- If unable to respond in time, M-PESA uses the configured default action

## Going Live

After testing in the sandbox, you're ready for production.

### Requirements

1. **M-PESA Account** — A live Pay Bill, Till Number, or B2C shortcode
2. **M-PESA Portal Access** — Business Administrator or Business Manager role created
3. **API Users** — At least one API operator with the correct role assigned
4. **Callback URLs** — Publicly accessible HTTPS endpoints
5. **Passkey** — Provided via email after go-live (for M-PESA Express)

### Go-Live Steps

1. Log in to the [Daraja Portal](https://developer.safaricom.co.ke/)
2. Navigate to the **GO LIVE** tab for your app
3. Fill in the required fields:
   - **Organization Shortcode:** Your live Pay Bill/Till/B2C number
   - **Organization Name:** Your business name (remove special characters)
   - **M-PESA Username:** Business Administrator or Business Manager username from the M-PESA portal
4. An **OTP** is sent to the phone number linked to the M-PESA portal user profile
5. Submit the go-live request
6. Upon approval, production endpoints and credentials are emailed to you

### Production Support

- **Email:** apisupport@safaricom.co.ke
- **M-PESA Business Onboarding:** M-PESABusiness@Safaricom.co.ke
- **Incident Management:** Raise an incident on the Daraja portal self-service section

## Best Practices

1. **Token Management:** Cache access tokens and regenerate before expiry.
2. **Unique IDs:** Always use a unique `OriginatorConversationID` per request to prevent duplicate processing.
3. **Error Handling:** Implement proper retry logic with exponential backoff for transient errors.
4. **Callback Robustness:** Ensure callback URLs are always available and respond promptly.
5. **Reconciliation:** Use Transaction Status API or Pull Transactions API as secondary reconciliation mechanisms.
6. **Logging:** Log all API requests and responses for audit and debugging.
7. **Security:** Never expose Consumer Key/Secret or Security Credentials in client-side code.
8. **Rate Limiting:** Respect API rate limits. Implement throttling in your application.
