# Account Balance API

By Safaricom

Enquire the balance on an M-Pesa BuyGoods (Till Number).

**Endpoint:** `POST https://sandbox.safaricom.co.ke/mpesa/accountbalance/v1/query`

---

## Overview

The M-PESA Account Balance API by Safaricom enables organizations to programmatically check their M-PESA account balances. This is essential for automating financial processes, monitoring account status, and ensuring sufficient funds for operations.

### Key Features

- **Real-time Balance Inquiry:** Instantly retrieve your M-PESA account balance.
- **Secure Access:** Authentication and authorization ensure only permitted entities access the balance.
- **Automated Responses:** Receive automatic acknowledgments and responses to inquiries.

## How It Works

1. **Request Setup and Submission:** The Organization configures the request with all necessary parameters and sends it to `https://sandbox.safaricom.co.ke/mpesa/accountbalance/v1/query`.

2. **Acknowledgment by Daraja:** Upon receiving the request, Daraja performs validation (ensures required parameters are present and correctly formatted), authorization (confirms the Organization has necessary permissions), and authentication (verifies the Organization's identity). Daraja sends a synchronous acknowledgment back to the Organization.

3. **Forwarding to M-PESA:** Daraja forwards the validated, authorized, and authenticated request to the M-PESA system for further processing.

4. **Acknowledgment by M-PESA:** M-PESA receives the request, performs initial validation, and sends an acknowledgment response back to the Organization.

5. **Internal Processing:** M-PESA processes the request internally, verifying details and preparing the account balance information.

6. **Response Callback:** Once processing is complete, M-PESA sends the account balance response to the Organization via the callback URL specified in the initial request.

7. **Status Check on Failure:** If M-PESA is unable to deliver the callback (e.g., due to network issues), there are no automatic retries. The Organization can manually check the transaction status via the M-PESA portal.

> **Note:** This API is asynchronous and can be accessed via the internet, VPN, or Multiprotocol Switch.

## Getting Started

### Prerequisites

- Create a Daraja Account on the Safaricom Developer Portal.

This API is asynchronous and is used to check the status of various M-PESA transactions, including C2B, B2B, B2C, Reversal, and IMT.

### Authentication

Generate an access token before making API calls. See the [Authorization API](./Authorization.md). Token generation is automated in the simulator section.

## Request Body

```json
{
  "Initiator": "testapiuser",
  "SecurityCredential": "SAFVNChNHfVtXEZMBuVo+a1Hwr+DtrUVN3zVg==",
  "CommandID": "AccountBalance",
  "PartyA": "600000",
  "IdentifierType": "4",
  "Remarks": "ok",
  "QueueTimeOutURL": "http://myservice:8080/queuetimeouturl",
  "ResultURL": "http://myservice:8080/result"
}
```

### Request Parameter Definition

| Name | Description | Type | Sample Values |
|------|-------------|------|---------------|
| CommandID | A unique command passed to the M-PESA system. Max length is 64. | String | AccountBalance |
| PartyA | The shortcode of the organization querying for the account balance. | Numeric | 600772 |
| IdentifierType | Type of organization querying for the account balance. | Numeric | 4 |
| Remarks | Comments that are sent along with the transaction. | String | tests |
| Initiator | API user's credential/username used to authenticate the transaction request. | Alpha-Numeric | Testapi772 |
| SecurityCredential | Initiator password is encrypted to give the security credentials. | String | EToK4lNR... |
| QueueTimeoutURL | The end-point that receives a notification in case of a timeout. | URL | https://ip:port/path or domain:port/path |
| ResultURL | Destination URL which Daraja should send the result notification to. | URL | https://ip:port/path or domain:port/path |

## Use Cases

### Financial Reconciliation
A business needs to reconcile its daily transactions with its M-PESA account balance. The organization schedules a balance query at the end of each business day to ensure all transactions are accounted for and reconciled with their internal records.

### Automated Payment Systems
An e-commerce platform automates payments to vendors through M-PESA. Before initiating payments, the platform queries the M-PESA account balance to ensure there are sufficient funds to cover all outgoing payments. If funds are insufficient, the platform triggers an alert for manual intervention.

### Fraud Monitoring
A financial institution uses M-PESA for various transactions and needs to monitor fraudulent activities. The institution sets up periodic balance checks to detect any unauthorized withdrawals or discrepancies in account balances, helping to identify potential fraud quickly.

### Cash Flow Management
A retail chain manages its cash flow by monitoring the balance of multiple M-PESA accounts used across different branches. The head office queries the balance of each branch's M-PESA account at regular intervals to manage and allocate funds effectively.

### Payroll Processing
A company uses M-PESA to disburse salaries to its employees. Before processing payroll, the company queries the account balance to confirm there are enough funds to cover the total payroll amount.

### Bill Payments
A utility company allows customers to pay bills via M-PESA and needs to monitor the received payments. The company queries the account balance periodically to track the total payments received.

## M-PESA Organization Portal

The M-PESA organization portal is a platform designed for businesses and organizations to manage their financial transactions through M-PESA services.

### Portal Features
- **Transaction Management:** Monitor and manage transactions, generate reports, and reconcile accounts.
- **Account Management:** Manage multiple user accounts with different access levels within the organization.
- **Bulk Payments:** Facilitate bulk payments to employees, suppliers, and other beneficiaries efficiently.

### Access
URL: `https://org.ke.m-pesa.com/orglogin.action`

To access the Organization portal, you need to have a Business Administrator role created under your business short code (Pay Bill/Till). The first step is to ensure the settlement option set to your short code is Bank via a Head Office application.

### First-Time Login
1. Launch the link from any browser: `https://org.ke.m-pesa.com`.
2. Enter the Short code (Bulk payment number).
3. Enter the Business Administrator username received via email.
4. Enter the first-time password received via email (case-sensitive; full stop is not part of the password).
5. Enter the Verification Code displayed then click login.
6. Enter OTP to proceed to the change password page.
7. Set a new password, confirm password, and set security question and answer.
8. Submit to successfully activate the Business Administrator account.

After activation, log in using username, shortcode, password, verification code, and OTP received via SMS.

### Account Types in Organization

| Account Type | Description |
|-------------|-------------|
| MMF/Working/M-PESA Account | When an organization wants to make a business withdrawal, funds are transferred to this account before the withdrawal request is made. |

### Portal Roles

#### Business Administrator
- Creates other system users and gives them roles (Web Operator, Business Manager, Business Auditor).
- Cannot view transactions.
- Created by Safaricom (M-PESABusiness@Safaricom.co.ke).

#### Business Manager
- Views statements, initiates transactions, approves/rejects transactions.
- Withdraws funds from M-PESA.

#### Creating a Business Manager
1. Log in to the Organization portal as the Business Administrator.
2. Select operators → click **Add**.
3. Enter the username of the operator.
4. Select access channel as **Web**.
5. Select web profile default rule profile.
6. Assign role: **Business Manager** and set **Restricted ORG API PASSWORD**.
7. Enter KYC information and submit.

#### Creating an API Operator
1. Log in as the Business Administrator.
2. Select operators → click **Add**.
3. Enter the username of the API initiator.
4. Select access channel as **API**.
5. Select web profile default rule profile.
6. Assign role: look for **ORG B2C API initiator**, **Balance Query ORG API**, **Transaction Status query ORG API** roles.
7. Enter KYC information and submit.
8. Set password via Business Manager (My Functions → Operator Management → search API username → operations → set password). Avoid using `@` or `.` in the password.

## FAQs

**What is the M-PESA Account Balance Query API?**
Allows organizations to programmatically check the balance of their M-PESA accounts. Provides a secure and automated way to retrieve real-time account balance information.

**Who can use it?**
Any organization with an M-PESA account registered for Daraja API access with the necessary permissions and credentials.

**What information is required?**
Short code, access token, Command ID (AccountBalance), PartyA, IdentifierType (4), callback URL, optional Remarks and QueueTimeoutURL.

**How does authentication work?**
OAuth 2.0. Obtain an access token by sending a request to the OAuth endpoint with client key and client secret.

**What is the typical response time?**
Synchronous acknowledgment within seconds; final account balance response usually delivered within minutes.

**What happens if the callback URL is unreachable?**
No automatic retries. Organization must manually query the transaction status using the unique transaction ID.

**Can I check the balance of multiple accounts?**
Yes, separate requests for each account with the specific short code.

**Is the balance provided in real-time?**
Yes, reflects the real-time balance when the query is processed.

**What security measures are in place?**
OAuth 2.0 authentication, HTTPS encryption, parameter validation, and permission checks.

**Can I automate balance checks?**
Yes, by scheduling balance query requests at regular intervals.

**Can third parties check my balance?**
No, third parties can only check the balance of their own shortcode. Only the initiator associated with the merchant can request a balance query of the merchant store within the hierarchy.

**What should I do if I do not receive a response?**
Check the QueueTimeOutURL for timeout notifications and ensure your ResultURL is correctly configured and reachable.

**How do I generate a Security Credential?**
Security credentials are generated by encrypting the base64-encoded initiator password with M-PESA's public key (X509 certificate) using RSA with PKCS #1.5 padding. The resulting encrypted byte array is then base64 encoded.
